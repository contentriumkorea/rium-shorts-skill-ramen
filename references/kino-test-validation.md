# 실제 Kino 30초 테스트에서 확인한 점

2026-11-05 사용자 요청으로 모아 둔 레퍼런스 01·07을 사용한 내부 편집 시험이다. 본편 촬영본이나 공개용 축제 홍보물이 아니다. 실제 프로젝트·검수 기록은 제작자의 비공개 작업 기록에 별도 보관하며 공개 패키지에는 포함하지 않는다. 이 사례의 좌표를 다른 편의 고정 템플릿으로 적용하지 않는다.

## 실제 수행

- 로컬 MP4 2개를 Kino에 가져오고, 별도 1080×1920/30fps 프로젝트를 생성했다. 기존 시험 프로젝트는 수정하지 않았다.
- `timelineEdit`로 영상 8구간을 0~900프레임에 배치했다. 01은 인파·백팩·조리·라면·시식, 07은 김밥 장면이다. 합계 30초다.
- 07의 **원본 혼합 오디오** 0~30초를 독립 Audio 레이어로 두고 테스트용으로 볼륨·시작/끝 페이드를 적용했다. 별도 준비 BGM이나 분리된 악기 음원이라고 부르지 않는다. 소스 영상 원음은 이 내부 몽타주에서만 음소거했다.
- 중앙 새 자막과 상단 고정 제목을 비교 초벌로 작성하고 `projectScreenshot`에서 실제 가림을 확인했다. 원본 합성 자막은 보존했다.
- 조리 문구는 위 여백으로 이동·축약, 음식/김밥/마지막 한 입의 새 문구는 생략했다. 상단 고정 제목도 껐다.
- 시식 문구를 상단으로 옮긴 첫 수정에서는 고개를 드는 순간 눈과 겹쳤다. ‘맛은?’으로 줄여 좌측 여백에 두고 해당 구간을 다시 검사했다. 새 문구의 하단 이동이 항상 해답은 아니다.
- 원본 내부 장면전환을 확인해 백팩 요점은 4~6.8초로 줄였다. 조리 문구는 처음 11~14초로 줄였지만 전체 렌더의 13.9초에서 새로 등장한 요리사 눈과 겹치는 것을 발견했다. 소스 35.5~37.1초를 다시 확인하고 최종 11~13초로 줄여 얼굴 등장 전에 끝냈다. 편집기 표본 검수 뒤에도 실제 출력 검수를 생략하지 않는다.
- Kino 주석으로 문제·수정 이유를 남기고 화면 재검수 후 해결 처리했다. 라이브 mount의 오류는 없었다. 독립 영상·자막·오디오 레이어와 원본/수정 소스 스냅샷을 보존했다.

## 관찰된 도구 동작

JSX 구조를 바꾸면 이전 clipId를 계속 쓸 수 없는 경우가 있어 `timelineGet` 재조회가 필요했다. 주석과 편집 연산의 혼합 호출은 거절됐고 분리 호출은 성공했다. 개별 자막 인스턴스 타이밍 편집이 전용 컴포넌트 복사본을 만들기도 했다. 현재 소스를 다시 읽어 수정 대상과 공통 스타일의 범위를 확인한다.

## 출력·검수 상태

Kino에서 30초·900프레임·1080×1920·30fps H.264/AAC 전체 파일을 출력하고 전체 디코딩을 확인했다. 이 PC의 해당 전체 렌더는 약 15분 15초가 걸렸다. 모든 PC/편집의 속도로 일반화하지 않는다. 출력 검사에서 추가 가림이 발견돼 Kino 소스의 문구 종료를 수정하고 13~14초 30프레임을 Kino에서 다시 출력했다. FFmpeg로 전체 렌더의 390~419프레임만 그 출력으로 교체·결합했다. 최종 30초·900프레임, 전체 디코딩, 출력 표본과 수정 구간을 검사했고 원래 AAC payload가 그대로임을 해시로 확인했다. 모든 시각 편집은 Kino 프로젝트에 남아 있으며 최종 MP4의 구간 결합 경로도 기록했다.

구간 출력 결합은 이 시험의 지원 작업이지 모든 편의 필수 방식이 아니다. 쓰려면 변경 범위 밖 코드·미디어·타이밍·음성이 동일하고, 정확한 프레임 수·경계·오디오 보존을 확인해야 한다. 범위를 특정할 수 없거나 전역 변경이면 전체 렌더를 다시 검증한다. 이미 실패한 Kino 작업을 제한 우회용 다른 도구로 재현하지 않는다.

초기 비교 초벌 전체 렌더는 불필요한 중복 렌더를 줄이기 위해 취소했고, 가림이 있던 28초 지점 한 프레임의 Kino 내보내기는 완료했다. 취소된 0바이트 출력은 `.cancelled`로 구분했다.

최종 구간 출력 완료 뒤 context 조회는 주간 MCP 호출 한도로 **실행되지 않았다**. 이후 가이드·제품 문서 조회도 거절됐지만, 설정 목록 조회와 설정 화면 열기는 성공했다. 일부 도구의 거절을 모든 편집·렌더 불가나 유료 전환 필수로 일반화하지 않는다. 추가로 요청된 2초 GPU 시험은 exportVideo 자체를 호출하지 않았으므로 그 렌더 명령의 거절이 확인된 것도 아니다. 도구별 실행·거절·미시도 상태를 따로 보고하고, 이미 거절된 작업을 다른 경로나 계정으로 우회하지 않는다.

마지막으로 다시 연 요리사 가림 주석은 소스·출력 수정은 완료됐으나 앱 안에서 다시 resolve하지 못했다. 이후 작업은 해당 도구의 현재 허용 상태와 실제 타임라인을 확인한 뒤 진행한다.

GPU 프로세스와 GPU 메모리 사용은 관찰했지만 렌더 중 하드웨어 인코딩 여부는 측정하지 않았다. 720p/중간 품질은 비교 후보일 뿐 속도 개선이 검증된 설정이 아니다. 전체 클라우드 끄기 항목도 확인하지 못했다. 이 스킬은 GPU 최적화 완료나 오프라인 전용 편집을 보장하지 않는다.

직접 청취, 실제 휴대전화 Instagram UI, 독립된 자동 얼굴/음식 가림 검출, `addCaptions` 전사 생성, ElevenLabs, 다른 PC 재연결은 이 테스트로 검증하지 않았다. 에이전트가 실제 프레임을 관찰해 판단·수정하는 흐름을 시험했다. 원본에 박힌 자막의 가림까지 제거했다고 보고하지 않는다.

사용자가 명시적으로 레퍼런스 시험 편집을 요청한 범위에서만 참조 영상·혼합 음원을 썼다. 이 허용을 실제 본편의 자산 사용 권리나 공개·납품 승인으로 확대하지 않는다. 본편은 사용자 촬영본과 준비한 BGM 파일을 우선 사용한다.
