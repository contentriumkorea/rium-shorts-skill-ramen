# 프로젝트 연결과 재개

사용자가 지정한 실제 프로젝트 폴더나 현재 작업 디렉터리에서 시작한다. 기존 `README.md`, `codex/프로젝트 안내.md` 또는 편별 인덱스를 먼저 읽고 실제 파일과 대조한다. 특정 직원의 드라이브·계정·행사 문서·편집기 ID를 기본값으로 사용하지 않는다.

현재 사용하는 편집기를 대화·편 인덱스·실제 프로젝트 파일에서 확인한다. 이미 정해진 편집기를 다시 묻거나 다른 도구로 바꾸지 않는다. 정보가 없거나 자료가 충돌할 때만 한 번 확인하고 [편집기 연결·실행](editor-workflow.md)에 따라 실제 제공 도구와 지원 범위를 파악한다. 앱 이름만으로 네이티브 편집·포맷 변환이 가능하다고 가정하지 않는다.

촬영본·레퍼런스·준비 BGM의 위치와 기존 편 번호를 확인한다. 기존 구조가 `Footage`, `Sequence`, `Export`, `etc`를 사용하면 유지하고, 다른 구조라면 그 프로젝트 기준을 따른다. 없는 경로를 임의로 만들거나 앱의 관리 폴더·미디어 연결을 옮기지 않는다. 일정·장소·납품 조건은 현재 프로젝트 문서에서 확인한다.

새 프로젝트에 동봉 에셋을 준비할 때는 [초기 세팅](asset-setup.md)으로 승인된 프로젝트별 사본과 실제 편집기 미디어 연결을 기록한다. 재개할 때는 기존 사본·설정 기록과 연결 상태를 먼저 확인해 중복 복사하지 않는다. 이번 도구가 관리한 임시 다운로드와 기존 에셋을 구분하고, 다른 프로젝트 참조나 연결 확인이 남은 파일을 자동 정리하지 않는다.

이 패키지의 [8편 분석](reference-analysis.md)은 제작 당시 모은 레퍼런스에 대한 사례 연구다. 원본 영상·음원·내부 운영 문서·실제 편집 프로젝트는 배포에 포함하지 않는다. 번호 01~08은 사례 식별자이며 새 사용자의 촬영본 번호가 아니다. 분석은 일반 편집 원리로 활용하고 실제 컷·문장·배치·음악은 사용자가 제공한 자산으로 결정한다.

과거 특정 편집기에서 30초 내부 시험을 수행한 범위는 [테스트 검증](editor-test-validation.md)에 기록돼 있다. 이 기록은 현재 편집기 선택을 강제하지 않으며 다른 앱의 자동 편집·임포트·GPU 성능 검증으로 확대하지 않는다. 사례의 내부 프로젝트를 현재 본편으로 자동 편입하지 않는다.

호출 예:

```text
$rium-shorts-skill-ramen
촬영본은 [폴더]. 인파와 먹거리 중심이며 대본은 없음.
45~90초 사이에서 장면에 맞는 길이와 이유를 추천해줘.
기존 프로젝트의 편집기로 두 방향과 자막 배치를 추천한 뒤 초벌을 만들어줘.
```

대본이 있으면 “첨부한 원문 대본의 정상 발화·호흡·장면에 맞춰 길이를 정해줘”처럼 요청한다. [편집 기준](editorial.md)에 따라 예상 길이와 실제 확정 길이를 구분하고, 과거 시험의 30초를 새 본편의 기본값으로 가져오지 않는다.

Claude에서는 `Rium Shorts Skill - ramen 스킬로 ...`처럼 요청하거나 해당 환경의 스킬 선택 방식을 사용한다. 네이티브 편집에는 대상 편집기의 실제 연결·권한이 필요하며 준비 자료 완료와 앱 적용 완료는 구분한다. 음성 생성은 선택한 서비스의 실제 연결과 요청 범위를 확인한다. 클라우드 중단 지시가 있으면 확인되지 않은 업로드·분석·동기화를 새로 시작하지 않는다.
