# 촬영본에 맞는 자막 조합과 유연한 재편집

**먼저 화면을 보고 제안하고, 편집 결과를 보고 다시 판단한다.** 중앙·하중앙·상단 타이틀은 고정 템플릿이 아니라 조합할 수 있는 역할이다. 사용자가 자막을 중앙에 두라고 한 경우에도 중요한 얼굴/상황을 가리는 구간을 알려주고 대안을 보여준다. 원하는 스타일과 실제 가독성을 함께 살린다.

## 1. 촬영 소스에서 배치 근거 찾기

좋은 컷 후보마다 세로 크롭 후 다음을 확인한다: 얼굴/눈/입, 음식을 집는 손·젓가락·면, 그릇/제품, 간판·메뉴, 인파의 규모를 보여주는 중심 통로, 행동의 시작과 결과. 정지 프레임 한 장의 빈 곳이 아니라 **해당 구간 동안 피사체가 지나가는 범위**를 본다. 시작·중간·끝과 큰 움직임/장면전환 직전을 표본 확인하고, 가림 위험이 있으면 그 구간을 더 촘촘히 본다.

프레임/모델이 얼굴을 못 찾았다고 빈 공간으로 확정하지 않는다. 사람이 거의 없더라도 라면·김·손동작·상황을 가릴 수 있다. 장소/메뉴 글자를 읽게 할 컷은 자막이 기존 글과 경쟁하지 않는지도 본다.

먼저 글자의 출처를 **원본에 합성된 글자 / Kino에서 만든 제목·요점 / 생성된 전사 자막**으로 구분한다. 원본 자막·제목·워터마크는 새 레이어의 위치를 바꿔도 움직이지 않는다. 기존 문구가 충분하면 새 자막을 더하지 않는 안도 비교한다. 원본 글자를 이동·제거했다고 보고하거나 워터마크를 자동으로 지우지 않는다. 이를 감추기 위한 확대·크롭이 얼굴·음식을 잘라내는지도 확인한다.

## 2. 실제 장면에 맞춰 제안할 조합

| 조합 | 어울리는 소스 | 피하거나 조정할 때 |
|---|---|---|
| 중앙 훅 → 하중앙 진행 자막 | 도입은 인파 전경, 본문은 얼굴/제품이 중앙에 있는 방문기 | 음식/손이 하중앙으로 들어오면 본문도 이동/축약 |
| 중앙 중심, 필요 컷만 다른 빈 공간 | 화면 위아래가 복잡하고 중심 여백이 반복되는 장면 | 표정/행동이 중앙을 차지하면 그 컷만 override |
| 상단 대주제 계속 + 하중앙 본문 | 하나의 질문을 끝까지 설명하고 상부 여백이 충분함 | 두 글층이 화면을 과밀하게 하거나 얼굴/간판을 가리면 주제를 줄이거나 일부 해제 |
| 상단 대주제 계속 + 중앙 핵심어 | 정보가 적고 중앙에 짧게 강조할 공간이 있음 | 인파·제품의 핵심이 중앙이면 이 조합을 추천하지 않음 |
| 초반 제목만 → 무자막/간헐 자막 | 표정·먹는 행동·현장음이 이야기 자체인 몽타주 | 필요한 이용 정보가 있으면 짧게 보완 |
| 시간/장소 챕터 + 이동 가능한 경험 자막 | 역→축제장→시장의 여정, 시점/장소가 실제로 바뀜 | 작은 화면에 시간·장소·대제목·본문을 동시에 중첩하지 않음 |

이를 여섯 가지 메뉴로 한꺼번에 사용자에게 고르게 하지 않는다. 분석한 촬영본과 의도에 맞는 2개 정도만 제시한다. 각 안에 첫 문구, 진행 방식, 자막 조합, 실제 장면의 적합 이유를 붙인다. 폰트·색·좌표 수치 선택을 초보 편집자에게 떠넘기지 않는다.

예: “면을 들어 올릴 때 화면 중앙을 크게 쓰고 있어서, 도입 문구만 중앙에 두고 본문은 하중앙의 빈 공간을 쓰는 안을 추천합니다. 상단 주제를 계속 두는 안도 가능하지만, 간판을 보여주는 두 컷에서는 잠깐 해제하는 편이 낫겠습니다.” **그 장면을 실제로 확인했을 때만** 이렇게 말한다.

## 3. Kino에 수정 가능한 상태로 반영

편의 기본 배치와 컷별 예외를 분리한다. 선택 가능한 대주제 on/off, 기본 자막 배치, 필요한 크기/색/위치 정도를 현재 schema-knobs 규칙으로 노출한다. 중요한 컷은 독립 레이어/클립으로 유지한다. 프레임마다 자동 추적해 자막이 흔들리거나 한 문장을 읽는 중 갑자기 이동하게 하지 않는다. 한 컷 안에서는 가능한 안정된 위치를 유지하고, 장면 경계/문장 경계에서 바꾼다.

전사 자막은 Kino가 만든 기존 JSON·컴포넌트를 단일 소스로 수정한다. 별도의 자막 JSON 복제본을 만들지 않는다. 인계 기록에는 실제 자막 소스 경로·clipId와 배치 결정/예외만 연결한다. 후킹 문구·대주제는 전사와 구분한다.

## 4. 편집 뒤 가림 검수 → 수정안 → 재검수

1. **초벌 실제 화면**에서 0초/2초 이내 훅 완성/최장 문장/타이틀+본문 동시/얼굴·음식 클로즈업/움직임/마지막 장면을 본다. 중요한 구간은 재생 또는 촘촘한 프레임 확인. 한 스크린샷으로 전편 통과라고 하지 않는다.
2. 각 문제를 `편 번호, timeline 구간, clipId, 가려진 피사체/상황, 현재 배치, 수정 후보, 추천 이유`로 설명한다. 예: “R03 7.2~8.4초에 중앙 자막이 면을 드는 손을 가립니다. 하중앙도 그릇과 겹치므로 이 컷은 좌상단 빈 공간에 한 줄로 줄이는 게 낫겠습니다.”
3. 해결 순서는 정해진 공식이 아니다. 위치 이동, 한 줄로 축약/분절, 표시 시간 조정, 상단 제목 축소/일시 해제, 덜 중요한 자막 생략, 대체 컷 선택을 비교한다. 아래로 내리면 Instagram 계정/설명 UI에 가릴 수 있으므로 안전영역도 다시 본다. 글을 무조건 작게 줄이거나 검정 박스를 크게 덮는 것으로 해결하지 않는다.
4. 요청 범위 안의 작은 가림·가독성 보정은 진행하고 전후 차이와 이유를 보여준다. 이미 정한 문장 뜻·전체 스타일·고정 타이틀 전략을 크게 바꾸는 경우에는 그 차이를 보여주고 선택을 받는다. ‘알아서 검수해서 고쳐줘’로 위임한 범위는 재승인하지 않는다.
5. 고친 구간의 이웃 컷, 문장 읽는 시간, 첫 2초 의미, 피사체와 플랫폼 UI 겹침을 다시 확인한다. 납품 렌더에는 검수용 안전영역 오버레이를 제외한다.

위치를 바꾼 직후 한 프레임이 좋아 보여도 완료가 아니다. 실제 TEST01에서는 상단으로 옮긴 문구가 고개를 드는 순간 눈과 겹쳐, 짧은 문구를 좌측 여백에 두는 두 번째 수정이 필요했다. 한 방향만 보지 말고 **문구가 보이는 동안의 머리·손·그릇 움직임**을 다시 본다. 음식이 화면 대부분을 채우면 새 자막 생략도 비교한다.

이미 편집된 소스는 선택한 하나의 구간 안에서도 컷이 바뀐다. 자막의 내용과 배치가 그 내부 전환 뒤에도 유효한지 확인한다. 백팩 장면 뒤 조리기 화면에 백팩 문구가 남거나, 팬 다음 키오스크 화면에 조리 문구가 남으면 노출 시간을 줄이거나 문장을 나눈다. 전체 영상 길이를 줄이지 않고 문구만 조정할 수 있다.

실제 출력에서도 각 문구 끝 부근과 내부 컷을 검사한다. TEST01에서는 편집기 표본 사이에 있던 요리사 등장 컷의 눈 가림을 전체 MP4에서 뒤늦게 발견했다. 해당 소스 범위를 좁혀 다시 보고 노출 종료를 앞당겼다. 새 문제를 찾으면 이전 통과 기록을 다시 열고 수정 후 출력까지 확인한다.

검수 기록: `layout_base`, `shot_overrides[{clipId,time_range,placement,reason}]`, `occlusion_reviews[{range,text_origin,observed_issue,fix,verification}]`. `text_origin`은 baked_in/authored_overlay/transcript_caption으로 구분하고, verification에는 실제 표본 시각·렌더 확인 여부를 적는다. 검사하지 못한 움직임/실기기 UI는 `not_checked`로 남긴다. 좌표나 얼굴 검출 결과가 아니라 **최종 영상에서 중요한 내용이 보이고 읽히는지**가 판단 기준이다. 에이전트가 프레임을 보고 수정한 검수를 자동 얼굴·음식 감지 시스템 검증이라고 부르지 않는다.
