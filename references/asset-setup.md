# 초기 세팅: 프로젝트별 에셋 준비와 다운로드 정리

## 편집 시작 전에

기존 프로젝트 안내·폴더·네이티브 미디어 연결을 먼저 확인한다. 프로젝트가 여러 개면 각각의 기준 루트와 자산 경로를 구분한다. 한 프로젝트를 정리한다는 이유로 다른 작업폴더나 공유 에셋 위치를 정리하지 않는다.

동봉 효과는 작업할 프로젝트 안에 **독립 사본**으로 준비한다. 기존 프로젝트의 분류를 유지하고, 아직 정한 위치가 없으면 `Footage/Effects/rium-ramen-point-effects/`를 출발점으로 쓴다. 이번 초기 세팅 요청으로 위임된 복사·정리는 반복 승인 없이 진행하되 원본 영상·기존 연결 자산 이동이나 덮어쓰기로 확대하지 않는다.

## 자동 준비 도우미

스킬 폴더에서 실행한다. 프로젝트 루트는 이미 존재해야 한다.

```text
python scripts/setup_project_assets.py --project "작업 프로젝트 경로"
```

기존 자산 분류가 다르면 프로젝트 안의 상대경로를 지정한다.

```text
python scripts/setup_project_assets.py --project "작업 프로젝트 경로" --asset-subdir "기존 에셋 폴더/rium-ramen-point-effects"
```

도우미는 MOV 6종·안내·매니페스트·미리보기 9파일을 검증해 복사하고 `.rium-assets-setup.json`에 해시·준비 상태를 기록한다. 동일 파일은 재사용한다. 하나라도 기존 내용과 다르면 전체 사전 검사에서 중단하며 자동 덮어쓰기·새 버전 폴더 양산·구버전 삭제를 하지 않는다. 링크·정션·기존 하드링크·프로젝트 밖 목적지·설치 스킬 안의 프로젝트는 거부하며 기존 파일을 보존한다. 여러 작업폴더가 있으면 각 프로젝트 루트로 따로 실행한다.

기본 실행은 설치된 에셋을 쓰므로 추가 다운로드가 필요 없다. 설치 스킬의 에셋 원본은 이후 다른 프로젝트에 필요하므로 유지한다. 네이티브 편집기가 현재 그 설치 경로를 참조하고 있을 수도 있다.

## 내려받은 파일의 자동 정리

동봉 파일이 없고 공식 효과 ZIP을 받아야 할 때만 공개 릴리스에서 SHA-256을 확인한 뒤 다음 옵션을 사용한다. 예문의 값을 실제 확인한 해시로 바꾼다.

```text
python scripts/setup_project_assets.py --project "작업 프로젝트 경로" --download --sha256 "확인한 ZIP의 SHA-256"
```

공식 효과 ZIP 한 개를 이번 실행 전용 임시 캐시에 받는다. 해시·정확한 ZIP 파일 목록·크기를 검사하고 작업폴더에 복사한다. 프로젝트 파일의 최종 해시와 준비 기록 저장이 성공하면 **이번 실행이 직접 받은 ZIP과 비어 있는 캐시 폴더만** 삭제한다. 압축 내용을 임시 폴더에 풀어 네이티브 편집기에 연결하지 않는다.

- 기존 `Downloads`, 이전 실행 캐시, 설치 폴더, 프로젝트 에셋·공유 폴더를 검색해 삭제하지 않는다. 도우미에는 임의 파일·폴더 삭제 인자가 없다.
- 실패·동시 변경·예상하지 않은 캐시 파일이 있으면 정리를 보류하고 남은 경로와 이유를 보고한다. 기록에 남은 오래된 경로를 읽어 재귀 삭제하지 않는다.
- 다른 도구로 다운로드할 때도 실행별 임시 위치와 파일·해시를 먼저 기록한다. 이번 다운로드임이 확인되고 필요한 파일이 모두 보존·검증된 경우에만 그 다운로드 원본을 정리한다. 출처·사용 여부가 불명확한 기존 파일은 자동 삭제하지 않는다.
- 스킬 배포·설치 ZIP도 이번 설치에서 관리한 임시 파일만, 설치 파일 및 프로젝트 사본 검증 후 정리한다. 공유 보관용 배포 ZIP과 편집 미디어는 다운로드 캐시로 취급하지 않는다.

## 연결 확인과 여러 프로젝트 보호

복사가 끝나면 네이티브 프로젝트가 실제로 참조하는 경로를 읽고 **해당 프로젝트의 새 사본으로 필요한 미디어만 연결**한다. 열림·재생·효과 크기·알파와 저장 상태를 확인한다. 파일 복사·해시 일치는 네이티브 연결 완료가 아니므로 연결을 확인할 수 없으면 `not_verified`로 남기고 필요한 재연결을 안내한다.

기존 설치 경로·공유 에셋·다른 작업폴더를 참조하던 프로젝트가 하나라도 있거나 참조 여부를 모르면 그 기존 파일은 그대로 둔다. 한 프로젝트의 재연결 성공으로 공용 원본이 불필요해졌다고 판단하지 않는다. 기본값은 프로젝트별 사본이며 중복 제거·하드링크·공유 경로 통합은 하지 않는다. 기존 편집기가 관리하는 폴더를 이동하지 않는다.

스킬 업데이트도 이 규칙을 따른다. 이전 설치 폴더를 참조하는 프로젝트가 있거나 연결 여부를 모르면 기존 에셋의 원경로와 바이트를 유지한다. 다른 위치의 백업만으로 원경로 연결이 보존되지는 않는다. 바뀌는 에셋은 별도 위치에 준비하고 각 프로젝트의 재연결을 검증한다. 새 설치가 성공했다는 이유로 기존 설치본·에셋을 자동 삭제하지 않는다.

준비 기록과 실제 에셋 경로·연결 검수·다운로드 정리 완료 또는 보류 이유는 [편별 관리](episode-management.md)에 연결한다. 동시에 쓰는 다른 앱이나 Dropbox 서버까지 잠금이 보장되는 것은 아니므로 파일 변경이 발견되면 중단하고 상태를 다시 확인한다.
