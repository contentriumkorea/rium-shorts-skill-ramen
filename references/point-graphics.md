# 불꽃 타이포·스티커·짧은 포인트 효과

## 목적과 선택

영상의 핵심 문구·행동·감정을 더 빨리 알아보게 하는 강조를 계획한다. 불꽃 타이포나 스티커를 ‘AI 티가 나는 장식’으로 일괄 배제하지 않는다. 반대로 화면이 비어 보인다는 이유만으로 도형·반짝임·파티클을 채우지 않는다. 실제 촬영본과 사용자의 스타일을 근거로 적합한 순간을 추천하고, 이미 위임된 편집 범위에서는 시안에 적용해 보여준다.

먼저 훅·조리·발견·놀람·만족 반응에서 포인트 후보를 고른다. `어느 구간 / 어떤 문구·행동 / 효과가 더하는 의미 / 표시 길이 / 놓을 여백`을 짧게 적는다. 기본 흰 자막만 제시하고 끝내지 말고, 적합한 순간에는 강조형 대안을 함께 제안한다. 담백한 인터뷰처럼 효과가 흐름을 해치면 생략 근거를 남긴다. 강조 지점의 개수·색·폰트·좌표를 전 편에 고정하지 않는다.

## 동봉 에셋부터 확인

[6종 파일·사용 안내](../assets/point-effects/README.md)와 [매니페스트](../assets/point-effects/manifest.json)를 먼저 읽고, 의미가 맞는 동봉 효과는 새 생성 없이 활용한다. 실제 파일 경로는 매니페스트 위치를 기준으로 해석한다. 동봉 효과는 2초 알파 MOV 6종이며, 편별 `graphics`에 effect_id와 선택한 파일·구간·크기·문구·합성 방식·검수 상태를 기록한다. 최대 가시 범위도 제공되지만 실제 촬영본과 편집기의 확대/모션을 반영해 다시 검사한다.

## 6종 효과군의 활용

아래 이름은 효과 선택 기준이다. 실제 파일·길이·코덱·배경 종류·검증 상태는 제공된 에셋 목록과 파일을 열어 확인한다. 목록에 이름만 있거나 파일이 없으면 준비된 에셋으로 간주하지 않는다.

| effect_id | 잘 맞는 순간 | 문구·화면과 조합 | 조정하거나 피할 때 |
|---|---|---|---|
| `fire` | 실제 열기 있는 조리, 매운맛 반응, 강한 도입 | 굵은 문구 위·뒤 불꽃 또는 글자 모양 마스크, 본문에서는 강도 낮추기 | 음식의 실제 불꽃·김과 혼동하거나 입·눈을 가릴 때 |
| `sparkle` | 음식·제품 첫 공개, 발견, 즐거운 디테일 | 제품 외곽 또는 짧은 핵심어 옆 반짝임 | 실제 물체의 품질·상태를 오인시키거나 모든 컷에서 반복될 때 |
| `impact` | 정보 반전, 예상 밖 크기·반응, 짧은 요점 | 순간적으로 나타나는 강조선·팝과 한 문구 | 단순 이동 컷, 긴 설명, 이유 없는 충격 연출 |
| `lightning` | 빠른 변화, 실제 놀람, 활기 있는 행동 | 문구 바깥쪽 번개·강조선, 짧은 진입 | 피사체를 가르거나 잦은 점멸로 문장을 읽기 어려울 때 |
| `hearts` | 맛본 뒤 만족, 가족·친구의 따뜻한 반응 | 표정 주변 여백의 작은 하트와 짧은 감상 | 확인되지 않은 감정·관계를 단정하거나 얼굴을 덮을 때 |
| `steam` | 뜨거운 음식·조리 문구의 감각적 강조 | 텍스트 주변의 스타일화된 김·열기 | 실제 음식에서 나온 김인 것처럼 합성해 상태를 오인시킬 때 |

2초 루프 MOV는 반복할 수 있는 짧은 재료이지 모든 포인트의 표시 길이가 2초라는 뜻이 아니다. 문장이 읽히는 시간과 행동의 의미에 맞춰 잘라 쓰거나 반복한다. 도입 효과가 훅을 늦추지 않도록 첫 2초 안에는 핵심 의미가 완성돼야 한다. 루프 길이·프레임률이 시퀀스와 다르면 해당 편집기의 해석을 확인한다.

## 보유 에셋·새 이미지·한국어 문구

1. 적합한 보유 에셋이 있으면 원본 파일과 사용 범위를 확인해 선택한다. 없거나 문구 형태와 맞지 않으면 요청 범위 안에서 적합한 이미지를 생성하거나 사용 가능한 에셋을 준비한다. 레퍼런스의 장식·타이포·워터마크를 프레임에서 그대로 잘라 복제하지 않는다.
2. 한국어 문구는 가능한 편집기의 네이티브 텍스트로 유지한다. 불꽃·스티커·하트·배경 장식은 별도 항목으로 두고 문구와 함께 이동·크기 조절할 수 있게 연결한다. 이미지 생성이 문구까지 정확히 만들었다고 가정하지 않고 실제 한글을 확인한다.
3. 글자 모양 자체에 불꽃이 차오르는 효과가 필요하면 선택한 편집기의 텍스트 마스크·매트·클리핑 지원을 확인한다. 수정 가능한 원문과 마스크용 원본을 보존하고, 외곽선·읽히는 글자 형태가 불꽃에 사라지지 않게 한다. 해당 기능이 없으면 문구 뒤·위의 별도 장식으로 같은 의미를 전달한다.
4. 생성 이미지를 움직이는 에셋으로 가공하는 경우 정지 이미지 생성, 모션 제작, 내보내기, 타임라인 합성을 별개 단계로 기록한다. 이미지 한 장을 받았다고 2초 루프 영상 제작이나 편집 적용을 완료했다고 하지 않는다. 실제 생성·가공·적용이 불가능하면 빠진 단계와 사용할 문구·배치·효과 지시를 인계한다.

## 동봉 MOV의 알파와 외부 에셋 합성

- **동봉 알파 MOV:** 확장자나 ‘transparent’라는 파일명만 믿지 않는다. 매니페스트의 실제 알파 채널·코덱·픽셀 포맷과 선택한 편집기의 지원 및 합성 해석을 확인한다. 프리멀티플라이드/스트레이트 알파의 해석 차이로 테두리가 검거나 밝게 뜨는지 본다. 동봉 효과는 알파로 합성하며 색키 기능을 전제로 하지 않는다.
- **MOV를 지원하지 않을 때:** 사용자가 선택한 편집기가 지원하는 알파 교환 형식과 현재 가능한 변환 수단을 먼저 확인한다. 실제 변환할 수 있을 때만 알파·색·길이·프레임률을 보존해 변환하고, 변환본의 디코드·가장자리·편집기 임포트 결과를 별도로 검수한다. 지원 형식이나 변환·임포트를 확인하지 못하면 그 단계를 미실행으로 남겨 인계한다. 동봉되지 않은 MP4·PNG 대체본이 있다고 안내하거나 임의로 편집기를 바꾸지 않는다.
- **별도로 가져온 색키 배경 영상:** 단색 배경을 가진 영상이며 그 자체가 투명 영상인 것은 아니다. 실제 외부 에셋을 선택했고 편집기가 키잉을 지원할 때만 배경 제거를 검토한다. 효과색까지 지워지거나 배경색이 가장자리에 남지 않는지 움직이는 전 구간에서 확인한다. 일반적인 H.264 MP4를 알파 포함 영상이라고 안내하지 않는다.
- **별도로 가져온 검정 배경 발광 효과:** 에셋이 그 방식으로 제작됐고 편집기가 지원하면 Screen/Add 같은 블렌드를 검토할 수 있다. 이는 알파나 색키와 다른 합성이다. 필요한 검정 외곽선·그림자까지 사라지거나 밝은 피사체가 과하게 날아가는지 확인한다. 동봉 MOV의 검정 외곽선을 제거하는 대체 합성으로 쓰지 않는다.

실제 파일이 제공하는 방식만 안내한다. 밝은 바탕과 어두운 바탕, 최종 촬영본 위에서 가장자리·색 번짐·반투명 영역을 확인하고 적용한 알파 해석·합성 방식·주요 조절값을 편별 기록에 남긴다. 외부 색키 에셋을 사용한 경우에는 키색도 기록한다. 에셋 미리보기가 깨끗하다는 이유로 최종 합성도 통과했다고 하지 않는다.

## 포인트 합성 검수

1. **문구·의미:** 한국어 철자·띄어쓰기·숫자가 맞고, 효과가 실제 장면의 의미를 살리는지 확인한다. 문구가 불꽃·광채 뒤로 숨거나 너무 빠르게 바뀌면 줄이거나 시간을 조정한다.
2. **전체 효과 범위:** 글자 상자뿐 아니라 불꽃 끝·외곽선·그림자·빛·입자와 모션 최대 범위를 [안전영역](instagram-safe-area.md)에 대조한다. 구간 시작·최대 확장·끝과 큰 움직임을 확인한다. 얼굴·눈·입·손·면·그릇·메뉴·인파 중심 동선은 [자막 가림 검수](caption-layout-review.md)와 같은 기준으로 보호한다.
3. **합성:** 알파·키잉·블렌드의 실제 적용 결과를 확인한다. 배경 사각형, 색 번짐, 잘린 불꽃 끝, 그림자의 사각 테두리, 글자와 장식의 어긋남을 수정한다.
4. **모션·루프:** 루프로 사용할 때는 경계를 포함해 여러 번 재생하고 멈칫함·깜박임·위치/밝기 점프를 본다. 첫 프레임과 마지막 프레임이 같다는 사실만으로 자연스러운 루프라고 판정하지 않는다. 컷 밖으로 남는 효과와 의도하지 않은 오디오 트랙도 확인한다.
5. **재수정·출력:** 텍스트와 장식을 따로 수정할 수 있는지 확인하고 실제 출력에서도 축소된 휴대폰 크기로 읽어 본다. 포인트 에셋 자체 검증, 특정 편집기의 임포트 검증, 촬영본 합성 검증을 각각 기록한다. 다른 편집기에서도 같은 결과가 나온다고 보장하지 않는다.

에셋 이름·출처·상태와 각 편에서 선택한 문구·구간·합성 방식은 [편별 관리](episode-management.md)에 연결한다. 파일이 없거나 직접 적용하지 못한 항목은 `planned` 또는 인계 상태로 남기고 `applied`·`render_checked`로 표시하지 않는다.
